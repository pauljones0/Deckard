## Fork improvements retained in the native design

`rust/core/src/engine.rs` owns one writer per physical deck and polls input between image writes. Pending images are latest-only; the key cursor survives coalescing so later keys remain serviceable. Successful writes alone update transport identities. Transient errors release the HID handle, retain the controller/document state and reconnect; pressed visual state is cleared on disconnect/page switches. Hardware enumeration filters supported USB IDs and Ulanzi interface 0. The patched native driver retains Studio, Mirabox 293S and Ulanzi D200 from SDK 0.2.1, including paired Mirabox input events and combined Ulanzi ZIP uploads, unique filenames, startup priming, keep-alive, phantom-slot suppression and framing-byte avoidance. Neo LED feature reports are padded to the upstream 32-byte format. Missing serials receive a USB-path-derived fallback; that identifier can change when Linux assigns a different HID path.

`render.rs`, `animation.rs`, `geometry.rs`, `cache.rs` and `media.rs` carry immutable byte-budgeted encoded caching, bounded decoded media, shared frames keyed by path, destination dimensions and playback settings, cached glyph rasterization, GIF transparency/disposal/frame delays, latest-only bounded FFmpeg output, separate strip rendering, rotation mappings and the fork's calibrated Plus background band. Plus XL uses 112-pixel keys, a 1200×100 logical strip and a rotated 100×1200 JPEG; header/touch coordinates remain logical as required by Elgato’s HID specification. Studio defaults to 144×112 and validated firmware geometry overrides model fallbacks. Source-deadline rendering and a bounded one-frame queue replace fixed polling; input polls remain between key writes. [Endpoint audit](rendering-endpoints.md). Static pages render only after a revision/input change. Unused media/children are released, including while disconnected, locked or showing a different page. The native implementation uses its own cache and scheduling mechanisms; Python timer-wheel, observer and object-identity internals are not imported.

`persistence.rs` retains atomic fsynced saves, directory syncing, symlink-aware target resolution, modes and orphan cleanup. `model.rs` preserves unknown legacy fields, quarantines malformed JSON, caches stickies, validates edited shapes and stores private native settings. Native page/state/device defaults survive restarts. `store.rs` stages/validates/switches directory installs with a recovery journal, bounds archive expansion and HTTPS downloads, retries transient failures, verifies SHA-256 and bundles available native plugins and media. Page imports do not overwrite an already installed native plugin.

`ipc.rs`, `plugin.rs`, `desktop.rs` and the launcher preserve single-instance ownership before USB startup, same-user IPC, bounded queues, process-group cleanup, lazy GUI startup and native desktop queries. Direct KDE/Mango/source-row backports are also retained in the historical Python tree so that source remains accurate for future comparisons. The native GUI uses schema controls instead of plugin-supplied GTK widgets.

## Verification and limits

Native tests exercise an independent rotation oracle, exact fork Plus-band calibration, strip/key wire dimensions, Studio rectangular keys, Mirabox/Ulanzi packet fixtures and combined ZIP framing, GIF delay/transparency/nonloop disposal, cache retention, interrupted JSON saves, corruption recovery, symlink/mode behavior, page-switch/rename/delete/state persistence, held-input actions, IPC uniqueness, a separately launched CLI/daemon, native ELF RPC, wrong-ID/blocked-stdin cleanup and interrupted install recovery. Packaging checks formatting, Clippy, fake-device startup, isolated GUI capture, relocated GUI startup and AppImage diagnostics.

This is a behavioral port, not binary compatibility or an exact GTK screen recreation. Native store catalogs contain native packages; Python stores/plugins/install scripts are retired. Icon selection uses the desktop portal. The GUI has no original GTK onboarding/spinner reset affordance. Physical USB, every desktop integration, arbitrary third-party native plugins and multi-day Rust soak behavior require separate tests on those environments. Legacy Python regression/soak results are not claimed as native coverage.
